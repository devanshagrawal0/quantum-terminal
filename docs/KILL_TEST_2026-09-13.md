# Kill-test of the 145 computed features — 2026-09-13

HANDOFF §8a asked one question: of the features `compute.py` builds, does any of
them predict what a coin does next? This is the first measurement. Script:
`scripts/kill_test.py`. Full table (435 rows): `data/kill_test_ic.csv`.
Log of the run: `data/kill_test.log`.

## What was tested, in plain words

- 16 coins (the ones with features): ADA ALGO ATOM AVAX BCH BNB BTC COMP CRV DASH
  DOGE DOT ETC ETH LINK SOL. Hourly bars 2020-01-01 → 2026-08-31, one reading per
  coin per day (the midnight UTC bar), 2,435 days.
- 145 features from the 8 `feat_*` tables (the handoff said 157; 145 is what the
  tables actually hold).
- For each feature and each day: rank the 16 coins by the feature, rank them by
  what their price did over the next 1, 3 and 7 days, and correlate the two
  rankings. Average that over all days. This is `hl/ic.py`, the same routine every
  other measurement uses. Ranking coins against each other each day cancels the
  market's common move by construction.
- 435 tests in total. About 5 would pass |t| > 2.5 by luck alone, so the bar for
  "survivor" was |t| > 3.3 on non-overlapping days AND an IC of at least 0.015.
- Self-tests passed: feeding the tool a coin's own future scored +1.000; random
  and shuffled features scored ≈0. So a zero below is a real zero.

## The trap, and the control for it

100 of 435 tests cleared the survivor bar. That is far too many to be real, and
the pattern gave it away: **every volatility measure** (rv_24h, rv_7d, rv_30d,
parkinson, garman_klass, rogers_satchell, yang_zhang, atr_pct, keltner_width,
bb_width, ewma_vol, bipower, semi_vol, var_95, cvar_95, range_pct, hi_lo_2d)
scored a strongly negative IC (−0.07 to −0.12) at every horizon.

With only 16 coins, a feature that ranks them the same way every day cannot be
told apart from "which coins did well over these six years". DOGE is always the
most volatile; the majors are always the least. So every candidate was re-run
with each coin's feature **frozen at its all-time average rank**. If the frozen
version scores the same, the feature is picking coins, not timing them.

Result: for the whole volatility cluster the frozen version explains almost
all of it (frozen IC −0.06 to −0.11 vs a leftover "timing" part of −0.01 to
−0.02). The price-LEVEL features say the same thing from the other side: a
higher price (BTC, ETH, BNB) scored +0.055 at 1 day. **Over 2020–2026 the big,
calm coins beat the small, wild ones in this set of 16. That is a fact about
these six years, not a signal.**

## What is actually left

**1. One-day reversal — the statistic is real, and it is not only an illiquid-coin thing.**
Everything that measures "how much did this coin just go up, relative to the
others" (r_1h, r_4h, r_12h, r_1d, r_3d, roc_5/10/20, rsi_7/14/21, vwap_dev,
px_vs_sma50/200, bb_pctb, kst, coppock, tsi, chande_mom, stoch_k, williams_r)
has a NEGATIVE IC at 1 day: the coins that rose most give some back the next
day. Full IC −0.02 to −0.04, t on 2,265 independent days −3.4 to −6.2. After
removing coin identity the timing part is −0.06 to −0.10 — this one is timing,
not coin-picking. It is gone by 3 days. `rev_1d` (the feature built for exactly
this) scored +0.0336.

`STRATEGY.md` already recorded a 1-day reversal at IC +0.034 on Hyperliquid
daily data and killed it as a trade: **net −20 bps/day after spread**, "lives
entirely in illiquid coins". Same number here, three decimals, from different
data — but on the 16 MOST liquid coins. So the "illiquid only" part of that
verdict was wrong. The economics were NOT re-measured here (returns are price
only, no fees, no funding). At an IC of 0.03 and daily turnover, fees decide
it, and the earlier measurement says fees win.

**2. Realized skew / tail ratio / entropy** show small timing effects
(|timing IC| 0.02–0.05 at 3–7 days, |t| 2.5–4.2) but full ICs under the 0.015
floor or just above it. Not a result. Worth a look only once there are more
than 16 coins.

**3. Everything else** — trend (ADX, aroon, MACD, ichimoku, supertrend, hurst,
golden cross), bands, volume-flow (OBV, CMF, MFI, force index, PVT), candle
patterns (doji, inside/outside bar, wicks), calendar-free risk measures
(sharpe_30d, sortino, calmar, variance ratio, autocorr) — **nothing.** ICs
within noise at every horizon, or coin-picking.

## So, honestly

- No feature in the set is a tradeable 3–7 day signal on its own. Not one.
- The only thing with real timing content is the 1-day reversal, and the repo
  already showed it loses to costs. New information: it is present in liquid
  majors too, so a cost re-test on the majors (spreads there are ~1 bp, not the
  20 bps that killed it) is the one follow-up this run earns.
- 16 coins is the binding limit on everything above. The 114 remaining coins'
  price history was being backfilled while this ran (HANDOFF §8c); once
  `compute.py --all` has features for them (§8b, disk-heavy, ask Dev), re-run
  `scripts/kill_test.py` and the coin-picking confound shrinks on its own.

## Follow-up, same day: the reversal on the majors, net of costs — DEAD

`scripts/reversal_majors.py` (reuses `validate_reversal.py`'s book, measured
Hyperliquid spreads and cost model unchanged; 6.7 years; "majors" = the N
tightest-spread coins; year-by-year split; a maker-fee line as a labelled
assumption). Table: `data/reversal_majors.csv`, log `data/reversal_majors.log`.

```
set (tightest spread)   raw IC      gross bps/d   cost   net (taker)   net (maker, assumed)
top 20  (<= 2.64 bps)   +0.0257       -5.0        13.0     -18.1            -10.4
top 40  (<= 4.33 bps)   +0.0348       -2.2        13.8     -16.1             -8.6
top 80  (<= 6.71 bps)   +0.0369       -4.0        15.0     -18.9            -11.6
all 172                 +0.0393       +1.4        16.7     -15.3             -8.6
        (best variant of each: vol-scaled, exit band .45; daily rebalance is worse)
```
Not one year is net positive on taker fees in any set (top-80 in 2023: +0.12,
noise). The pre-registered kill — "net ≤ 0 on taker for every N" — is met.

**The one thing worth keeping:** the rank IC is positive in every set while the
top/bottom-fifth book loses money BEFORE costs (top-20 gross −5 to −11 bps/day).
Both are true at once only if the relation is not a straight line: the biggest
movers keep going (continuation in the tails), the moderate movers give back
(reversal in the body). A standalone reversal cannot use that. A combination —
reversal conditioned on the size of the move and on volume — is exactly the kind
of feature SET Dev asked for next, and this is the first concrete candidate.

## Reproduce

```
python scripts/kill_test.py                  # ~16 min for 145 features + ~10 min control pass
python scripts/kill_test.py --tables feat_ret --horizons 1
```
Memory stays under ~120 MB: one table at a time, daily rows only.
